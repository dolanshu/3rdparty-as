中性、有产品感、不暴露运营商身份、暗示还有 adapter/plugin 围绕它。集团输出或开源都不违和。

备选，看定位

repo 名 适合场景

"ims-as-core" 推荐。内核 + 适配层的架构，后续好扩展

"inhouse-ims-as" 纯内部、强调与厂商设备区分

"ims-tas" TAS 是电信圈通用叫法（Telephony AS），内行秒懂

"ims-as-platform" 想做成多业务承载平台时用

"ims-service-layer" 偏架构描述，产品感弱一些

几个坑别踩

- 别加 
"3hk-" / 
"hutch-" 前缀——一旦要对外或给集团 OpCo，改名成本很高
- 别用 
"poc-"、
"demo-"、
"v2-" 这种前缀，一眼暴露出身
- 别用 
"inhouse-third-party-as" 当 repo 名，太长且读起来拧巴

如果按之前的思路做多厂商解耦，建议拆成这样一组，观感很像正经产品工程：

ims-as-core            # 业务逻辑内核
ims-as-adapter-hw      # 华为 S-CSCF / 融合 SDM 适配
ims-as-adapter-eric    # 爱立信适配
ims-as-ops             # 部署、监控、runbook

如果你的 AS 承载的是具体业务（比如防骚扰、彩铃），repo 名里带业务词反而更好记——告诉我业务是什么，我可以再给你一版更贴切的。
