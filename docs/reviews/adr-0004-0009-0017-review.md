## 1. 总体评价

三篇的决策**早已存在于 §0 账本与 `AGENT.md` §2 非目标中**，本次是补写论证而非新做裁决。因此评审的重心不是"决策对不对"，而是三件事：

1. **依据是否回到了原文。** 三篇的 Context 首段均直接引用 `AGENT.md` §2 非目标原文，Evidence 节逐条给出原文引文与文件位置。没有出现"凭记忆写引文"的情况。
2. **是否写明了接受的代价。** 三篇均有 Negative / accepted 小节，且列出的都不是"待办"，而是明知故犯的缺口（0004 无法自行满足放音、0009 超时即掉呼叫、0017 无法提供计费数据）。符合 ADR 注册表的纪律要求。
3. **是否越界。** 三篇均未给出容量或时间结论：0009 明确"超时值属运维参数，不在本 ADR 给容量或时间结论"、draining 期容量下降仅定性描述；0017 明确 O4 / D5 未决、不写死默认值。这与 `AGENT.md` §2「M6 实测之前不发布任何容量数字」一致。

结构上三篇与 ADR-0002 / ADR-0006 对齐：头部四行字段（Status / Date / Decides / 回应 REQ）→ `---` → Context → Decision → Consequences（Positive / Negative-accepted）→ Alternatives（表格含 Why not）→ Evidence → Related。

## 3. 发现清单与裁决

### 3.1 ADR-0004（不做媒体 / 媒体 seam）

| # | 发现 | 判定 | 裁决与处置 |
|---|---|---|---|
| F-0004-1 | 依据必须是 `AGENT.md` §2 非目标原文，不能是"网外做媒体不合适"这类概括 | 必须项 | 接受。Context 首段逐字引用非目标原文（含五项否定），三角路由与合规两条理由分别展开并回指架构文档 §9.1 原文 |
| F-0004-2 | 三角路由与合规两条理由如只写一句"绕路 + 合规"，会退化成口号 | 应展开 | 接受。两条理由各占一段：三角路由拆成带宽翻倍与时延增加；合规与 `AGENT.md` §2 LI 非目标并列，说明"能力位置决定合规责任位置" |
| F-0004-3 | seam 若只写"保留接口"，会变成随时可钻的口子 | 必须项 | 接受。Decision 第三条把 seam 定义为"接口定义 + 触发条件"两部分，触发条件限定为放音 / 录音 / 转码 / DTMF 四类，并写明启用必须重走 ADR 与需求流程（`AGENT.md` §3 文档链） |
| F-0004-4 | 已知缺口：放音 / 录音依赖运营商网内 MRF，且当前无可用 MRF 的交付中该需求不可满足 | 不阻塞 | 接受并显式登记。Negative 第一条写明这是**交付边界**、须写进与运营商的接口约定；Consequences 同时登记"seam 长期空置没人敢删"的成本。另如实写明当前 `platform/src` 下无媒体模块，不虚构已有接口实现 |

### 3.2 ADR-0009（ISSU 是 draining）

| # | 发现 | 判定 | 裁决与处置 |
|---|---|---|---|
| F-0009-1 | 常见误写："进程无状态，所以可以随便重启"。必须区分"不迁移状态"与"可以立刻杀进程" | 必须项 | 接受。Context 第二段专门论证这一区分，并引 ADR-0010「进程里没有状态，不代表进程上没有在途呼叫」 |
| F-0009-2 | 机制必须落到具体文件，不能只说"用 preStop" | 必须项 | 接受。Decision ②分编排侧（`deploy/helm/templates/deployment.yaml` 的 `preStop` + `terminationGracePeriodSeconds`）与内核侧（`ProcessShell.request_terminate` / `run_until_drained`）两半段，Evidence 逐条给出文件、符号与注释原文 |
| F-0009-3 | 硬超时若不给，Pod 会被永不结束的呼叫永久占住；给了又等于承认会掉呼叫 | 必须项 | 接受双写。Decision ④要求必须有硬超时，同时写明"超时属运维参数、本 ADR 不给容量或时间结论"；Negative 第二条写明超时即掉呼叫、**必须告警**而非静默 |
| F-0009-4 | 本决策建立在"当前栈状态不可序列化"这一**会变**的前提上，写成永恒结论即为隐患 | 不阻塞，但须登记 | 接受。Decision ⑤写明 E5 探针验证通过后本决策可被重评，且推翻必须新写 ADR、不得静默改变；Evidence 引 ADR-0019 §7 K6 与 §7 接受缺口第 3 条（E5 未验证），并如实写明"E5 目前连可执行的判定都没有" |

### 3.3 ADR-0017（不做 CDR）

| # | 发现 | 判定 | 裁决与处置 |
|---|---|---|---|
| F-0017-1 | 依据必须是 `AGENT.md` §2 非目标原文与 PRD REQ-NF-7 原文 | 必须项 | 接受。Context 首段逐字引用非目标原文；Evidence 逐字引 REQ-NF-7 全文，含"呼叫轨迹不是话单：它没有投递通道、不批价、不做网间结算" |
| F-0017-2 | 容易被误读为"不留任何证据"，必须说明被排除的是形式而非需求 | 必须项 | 接受。Context 第三段区分"不做 CDR"与"不留存证据"，并引 PRD US-3 场景说明查询方、查询键（Call-ID）与用途（投诉追溯 / 反诈举证） |
| F-0017-3 | "轨迹不是话单"若只写在文档里，下游仍可能拿它对账 | 必须项 | 接受。Decision ③要求该区别在**文档与代码中显式声明**，并说明原因（一旦用于对账就事实成为第二套 CDR，却没有投递与结算语义）；Evidence 引架构文档 §7 表格「**非话单**」标注 |
| F-0017-4 | 已知缺口：保留期（O4）与存储选型（D5）未决 | 不阻塞 | 接受并显式登记。Decision ④写明保留期属 O4、由客户合规要求决定、**未定之前不得写死默认值**（机制先落地、数值不落地）；Negative 第二、三条分别登记 O4 与 D5，第四条登记"逐消息全量、无采样减量手段"的存储压力 |
