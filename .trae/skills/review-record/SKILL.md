# Review Record（评审记录）

对 ADR / 设计文档 / requirement 的评审与 gap 处置流程。产出一份评审记录，并把每条 gap 追到明确判定。

## 一、何时使用

- 评审 ADR / 设计文档 / requirement，需要产出 review record
- 处理已有 review 的 gap（裁决、处置、独立复核、签字）

## 二、不变式（硬规则）

1. **每个阶段产出必须有独立的 review record 文件**，落 `docs/reviews/<slug>.md`；复查轮次用 `-round2` 等后缀并存，不互相取代。
2. **每条 gap 必须有 ID**（如 `G-P0-1` / `G2-P0-1`），并含位置、说明、建议修复。
3. **绝不留未判断的 open 条目**（最重要的一条）。每条问题最终必须落到三种判定之一：
   - `已修复` —— 必须附**当前磁盘的文件 + 行号**证据。
   - `非问题` —— 必须给一句话理由，然后关闭。
   - `需修复（未修）` —— 必须给**去向**（在哪个文件哪一节登记）与**触发条件**；能当场修的当场修。
   禁止出现无判定的措辞：`残留`、`待办`、`建议后续`、`属已知`、`一并订正`、`可接受`（未给理由的）。
4. **评审者、裁决者、处置者、复核者必须彼此分离**。写 gap 的 agent 不得自行宣布关闭；处置完成后必须由**独立复核 agent 回正文逐条实证**，不采信 Adjudication 表自述。
5. **签字是维护者的动作**。只有获得维护者明确授权才可代签，且必须如实记录授权基础与签署范围边界。

## 三、五阶段流程

0. **读文档 + 上游一致性检查**：读被评对象及其全部上游（`AGENT.md` / `plan.md` / 架构文档 / 相关 ADR / 注册表）。
1. **Gap 评审**：产出带 ID 的 gap 清单，按 P0（阻塞下一步）/ P1 / P2 分级。
2. **裁决**：填 Adjudication 表（格式见 `.trae/rules/review-adjudication.md`），逐条 `接受 / 部分接受 / 驳回` + 修改方案。
3. **处置**：按裁决改文档，回填状态列。
4. **独立复核**：换一个 agent，逐条回正文实证，判定 `真正关闭 / 表面关闭 / 未关闭`，并检查是否引入新不一致。
5. **签字 + 当前状态**：写 `## 当前状态（Current Status）` 节（一眼看到结论），再填签字节。

## 四、派发规则（subagent）

- 评审与探索用**只读** agent；处置与签字用 **writing** agent。
- **一个工作树同时只允许一个 writing agent**。
- 每个阶段换新 agent，不要用同一个 agent 自评自证。
- spawn prompt 必须自包含：目标、边界、验证命令、报告格式全部写进去；硬约束（如"不许 git commit"、"只许改这几个文件"）直接写进 prompt。

## 五、反面教训（本仓库实战得出，务必遵守）

1. **等价映射会掩盖未关闭项**：把新一轮 gap 映射到旧一轮 gap 时，必须逐条验证语义等价。曾有 13 条映射错 8 条，导致 7 条实际未关闭的 gap 被标成"已修改"。
2. **半同步比不同步更危险**：改了架构文档的决策条，就必须在同一次改动里同步该文件所有引用处（正文、状态机、未决清单、风险表）。曾有决策 8 改了但 §10/§12/§13 未改，制造出自相矛盾。
3. **「已修复」必须带当前行号**：文档一经编辑行号即漂移，引用前必须重新 grep 核实，不得照抄上一轮的行号。
4. **复核要查"表面关闭"**：有对应文字 ≠ 解决了原诉求。判定时必须回到 gap 原文逐句比对诉求是否完整兑现。
5. **不要自行扩大范围**：只修清单要求的内容，不做"顺手改进"。

## 六、文件模板

```markdown
# Review Record — <评审对象>

- **评审对象**：<路径>（状态：Draft / 未提交）
- **评审日期**：YYYY-MM-DD
- **评审人**：<身份；是否最终签字>
- **评审范围**：<列点>
- **评审结论**：<一句话；保留为历史>

---

## 当前状态（Current Status）

> 本节反映当前落盘现状；上方原始评审结论保留为历史。

- **一句话结论**：
- **gap 统计**：
- **门禁**：
- **签字状态**：
- **未闭环项**：无 / <逐条写明去向与触发条件>

---

## 1. 总体评价
## 2. Gap 清单（P0 / P1 / P2）
## 3. 一致性检查（与上游文档）
## Adjudication（裁决记录）
## AI 复核结论（Verification）
## 签字
```

## 七、唯一权威

完整协作守则见仓库根 `AGENT.md` §3.2、§3.3；Adjudication 表格式见 `.trae/rules/review-adjudication.md`。
